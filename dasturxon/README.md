# Dasturxon — маркетплейс домашней еды (Узбекистан)

Реализация по техническому заданию v3.0. В репозитории:

| Папка | Что внутри | Стек |
|---|---|---|
| `backend/` | API, бизнес-логика, фоновые задачи, WebSocket | Node.js 22, TypeScript, Express 5, PostgreSQL 16, Socket.io |
| `admin/` | Веб-панель: владелец, бухгалтер, поддержка | React 18, TypeScript, Vite, Ant Design, Recharts |
| `mobile/` | Приложение iOS/Android: покупатель и повар | Expo / React Native, TypeScript |
| `API.md` | Полное описание API и событий WebSocket | — |

## Быстрый старт (локально)

Нужны Node.js 22+ и PostgreSQL 16.

```bash
# 1. База
createuser -s dx && createdb -O dx dasturxon   # или своя строка подключения в DATABASE_URL

# 2. API (http://localhost:4000/api)
cd backend
npm install
npm run seed      # миграции + демо-данные
npm run dev

# 3. Админка (http://localhost:5173)
cd ../admin && npm install && npm run dev

# 4. Мобильное приложение
cd ../mobile && npm install && npx expo start
```

Демо-доступы: админка `owner@dasturxon.uz / admin12345` (а также `accountant@… / accountant123`, `support@… / support123`); покупатель `+998901234567`; повара `+998901110001…3`. В режиме разработки SMS не отправляются: код приходит в ответе API и выводится в лог сервера.

Через Docker: `docker compose up --build` (PostgreSQL и API), затем `docker compose exec api node dist/seed.js`.

## Режимы интеграций

Все внешние сервисы подключены через адаптеры. Без ключей платформа полностью работает в режиме **mock**: оплата и холд имитируются, курьер «едет» по карте, SMS пишутся в лог. Для боевого режима заполните `backend/.env` (образец в `backend/.env.example`):

| Сервис | Переменные | Что нужно от вас |
|---|---|---|
| SMS (Eskiz.uz) | `SMS_PROVIDER=eskiz`, `ESKIZ_EMAIL`, `ESKIZ_PASSWORD` | Договор с Eskiz и утверждённый шаблон SMS |
| Payme Business | `PAYMENT_PROVIDER=payme`, `PAYME_MERCHANT_ID`, `PAYME_KEY` | Мерчант Payme с доступом к Subscribe API (токенизация карт и холд) |
| Яндекс Go for Business | `DELIVERY_PROVIDER=yandex`, `YANDEX_GO_TOKEN` | Бизнес-аккаунт и OAuth-токен API доставки |
| Push | — (Expo Push Service) | Проект Firebase (Android) и ключ APNs (iOS) загрузить в EAS: `eas credentials` |
| AI-проверка кухни | `ANTHROPIC_API_KEY` | Ключ Claude API. Без ключа заявки идут только на ручную проверку |
| Карты в приложении | `EXPO_PUBLIC_YANDEX_MAPS_KEY`, `EXPO_PUBLIC_YANDEX_GEOCODER_KEY` | Ключи Яндекс Карт / Геокодера |
| Выплаты поварам | — (пока mock) | Договор с банком, у которого есть API массовых выплат на карты |

## Что реализовано (по разделам ТЗ)

- **3. Покупатель:** вход по SMS; профиль с обязательной картой; несколько адресов; лента с сортировкой «готово сейчас → расстояние → рейтинг», фильтрами, поиском и картой; карточка повара с расчётом доставки (Яндекс × 1,15, округление до 100 сум); корзина только одного повара; оформление с холдированием; трекинг в реальном времени; оценка с тегами; история заказов; удаление аккаунта.
- **4. Повар:** регистрация в 4 шага с AI-проверкой фото кухни; переключатель онлайн/офлайн; новые заказы с 5-минутным таймером, напоминание за 2 минуты, автоотмена с возвратом денег; кнопка «Готово» вызывает курьера; блюда с порциями (автоматически скрываются, когда порции закончились); баланс, история и досрочный вывод.
- **5. Доставка:** расчёт стоимости, вызов курьера, трекинг каждые 5 с, push «Курьер рядом» (< 300 м), учёт реальной стоимости и буфера 15%, повторный вызов курьера при отмене.
- **6. Выплаты:** начисление после доставки (×0,76), автоматические выплаты в пятницу в 10:00 по Ташкенту (защита от двойного запуска), повтор при ошибке банка, досрочный вывод с комиссией 1% и ручным подтверждением.
- **7. Админ-панель:** роли строго по таблице 7.1 (проверяются на сервере), дашборд, заказы с возвратами, повара и верификация, блокировки (поддержка — не больше 24 ч), покупатели, жалобы, финансы, Excel-отчёты (налоговый и все транзакции), сотрудники, настройки комиссии, журнал действий.
- **10, 13:** push-уведомления по таблице ТЗ через Expo Push (FCM + APNs), история и счётчик непрочитанных в приложении, bcrypt (12 раундов), JWT 15 мин + refresh 30 дней с ротацией, лимит SMS, точный адрес повара покупателю не передаётся, номера карт не хранятся — только токены.

## Отличия от ТЗ и открытые вопросы

1. **Раздел 12 (продвижение поваров) пока не реализован.** Его нет в этапах 1–4, поэтому оставлен на следующий этап.
2. **«AI-улучшение фото блюд» не сделано.** Claude анализирует изображения, но не редактирует их. Для улучшения фото нужен отдельный сервис обработки изображений.
3. **Частичные возвраты.** Payme отменяет чек только целиком, поэтому частичный возврат проводится вручную в кабинете Payme, а платформа учитывает его в отчётах и балансе повара.
4. **Налог 4% на дашборде.** В ТЗ он входит в «доход платформы». Но это деньги повара, которые платформа удерживает и перечисляет в налоговую, поэтому в отчётах налог показан отдельной строкой.
5. **Кто платит за возврат.** Часть возврата за блюда удерживается с повара (видна в его истории красной строкой), часть за доставку ложится на платформу. Это правило стоит подтвердить.
6. **Эндпоинты Яндекс Go** написаны по публичной документации API доставки. Их нужно сверить с вашим договором; проверено пока только в режиме mock.
