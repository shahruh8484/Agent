# Голосовой бот для подтверждения заказов (UZ/RU)

Бот звонит клиенту после заявки, подтверждает заказ и собирает адрес. Говорит по-узбекски,
а если клиент говорит по-русски — переходит на русский. Работа идёт по этапам:

| Этап | Что делаем | Статус |
|---|---|---|
| 0 | Текстовый тест: выбор модели (LLM), консольный чат, автопрогон сценариев | **в работе** |
| 1 | Голос в браузере: STT + TTS, замер задержки | — |
| 2 | Телефония: Asterisk + SIP, запись, перевод на оператора | — |
| 3 | CRM, очередь, повторные попытки, панель | — |
| 4 | Пилот на 10–20% лидов | — |
| 5 | Дообучение (LoRA) на записях | — |

## Этап 0 — что внутри

```
voicebot/
  .env.example              настройки (копируется в .env)
  stage0/
    prompts/system_prompt_uz.md   системный промпт бота (замените своим)
    prompts/product.md            факты о товаре (подставляются в промпт)
    bot.py                  «мозг»: промпт → модель → ответ в JSON
    chat.py                 консольный чат: вы — клиент
    scenarios.yaml          25 тестовых сценариев
    run_eval.py             автопрогон сценариев + отчёт
    compare.py              сводная таблица по моделям
    find_models.py          список свежих моделей на Hugging Face
    setup.sh / start_llm.sh / stop_llm.sh   установка и запуск модели
```

Бот отвечает строго в JSON:
`{"say": "...", "lang": "uz|ru", "action": "continue|confirmed|rejected|fake|transfer|callback|end", "fields": {...}, "callback_time": ..., "note": ...}`.
vLLM физически не даёт модели выйти из этого формата.

## Пошагово: запуск на RunPod

### 1. Арендовать сервер
1. [runpod.io](https://www.runpod.io) → **Pods** → **Deploy**.
2. Видеокарта: **L40S 48 GB** (или подешевле — **A40 / RTX A6000 48 GB**). Тип: **On-Demand** (не Spot).
3. Шаблон (Template): **RunPod PyTorch** (последняя версия).
4. **Edit Template**: Container Disk — `30 GB`, Volume Disk — `150 GB` (папка `/workspace` — тут хранятся модели, она сохраняется при Stop).
5. **Deploy On-Demand**. Через 1–2 минуты сервер готов.

### 2. Открыть терминал
У сервера: **Connect** → **Web Terminal** → **Start** → **Connect to Web Terminal**.

### 3. Скачать код и установить (один раз, ~10 минут)
```bash
cd /workspace && git clone -b claude/new-session-0ny4k5 https://github.com/shahruh8484/Agent.git
```
Если репозиторий закрытый, git спросит логин и пароль: логин — ваш логин GitHub, пароль —
токен (GitHub → Settings → Developer settings → Personal access tokens → Fine-grained,
доступ только на чтение к репозиторию Agent).
```bash
cd /workspace/Agent/voicebot && bash stage0/setup.sh
```
```bash
source /workspace/venv/bin/activate
```

### 4. Запустить модель (первый раз 5–20 минут — скачивание)
```bash
bash stage0/start_llm.sh
```
Ждите надпись `✅ Модель готова к работе.`

### 5. Поговорить с ботом
```bash
cd /workspace/Agent/voicebot/stage0 && python chat.py
```
Пишите как клиент. `/new` — новый звонок, `/json` — показать весь ответ, `/quit` — выход.

### 6. Автопрогон всех сценариев (~3–5 минут)
```bash
python run_eval.py
```
Отчёт: `stage0/reports/<модель>/report.md`. Удобно смотреть через **Connect → Jupyter Lab**:
открыть файл → правый клик → **Open With → Markdown Preview**. Файл `results.json` из той же папки
скачайте (правый клик → Download) и пришлите мне в чат — я разберу ошибки.

### 7. Сменить модель и сравнить
```bash
bash stop_llm.sh
```
```bash
nano ../.env
```
Поменяйте строку `MODEL=...` (сохранить: Ctrl+O, Enter, выйти: Ctrl+X), затем:
```bash
bash start_llm.sh && python run_eval.py && python compare.py
```

### 8. Закончили — ОСТАНОВИТЕ СЕРВЕР
В RunPod у сервера нажмите **Stop** ⏹. Остановленный сервер стоит только хранение диска
(~$0.07/ГБ·мес за Volume → 150 ГБ ≈ $10/мес). Совсем не нужен — **Terminate** (удалит и диск).
После Stop → Start заново выполнить только шаги 2, `source /workspace/venv/bin/activate` и 4.

## Какие модели сравниваем

Список свежих моделей на сервере:
```bash
python find_models.py
```
По умолчанию в `.env` стоит `Qwen/Qwen3-30B-A3B-Instruct-2507-FP8` — проверенная быстрая модель
(запасной вариант). Главные кандидаты на конец 2026 — новые семейства Qwen (3.5/3.6) и Gemma 4
(~27–31B); точные названия возьмём из вывода `find_models.py`. Модели Google (Gemma) и Meta (Llama)
требуют на Hugging Face нажать «Agree» на странице модели и вписать `HF_TOKEN` в `.env`.

Ориентир по памяти: на 48 ГБ — модели ~30B в версии FP8; модель ~30B без сжатия или ~70B в FP8 — 80 ГБ (A100/H100).

## Что проверяет автопрогон
- JSON корректный; правильное `action` в конце разговора (подтверждение / отказ / фейк / перевод / перезвон);
- нужный язык (узбекский или переход на русский);
- собран ли адрес (регион, район, улица, ориентир, время);
- признаёт ли, что виртуальный помощник, когда спрашивают;
- нет ли медицинских обещаний (проверка по словам — подозрительное показывается для ручной проверки);
- длина реплик и скорость ответа модели.

**Естественность узбекской речи машина не оценит** — читайте диалоги в report.md как носитель языка.
Клиента в автопрогоне играет та же модель — это удобно, но клиенты в жизни сложнее; поэтому
обязательно поговорите с ботом сами через chat.py.
