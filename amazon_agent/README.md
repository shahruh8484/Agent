# Amazon Affiliate Agent

Автономный агент, который сам:

1. **Подбирает товары на Amazon** под нишу (через официальный Creators API).
2. **Отбирает лучшие**: рейтинг, число отзывов, скидка, место в продажах.
3. **Делает сайт-витрину** под нишу: главная, страница каждого товара,
   тексты (LLM), раскрытие партнёрства. Сайт сразу доступен по
   `https://ВАШ_ДОМЕН/s/<ниша>/`.
4. **Запускает пуш-рекламу в PropellerAds** на страницы товаров своего сайта.
5. **Оптимизирует** кампании: отключает убыточные, кидает в чёрный список
   площадки без кликов, освободившийся бюджет отдаёт следующим товарам.
6. Повторяет цикл каждые `AGENT_INTERVAL_HOURS` часов.

Ниши агент тоже подбирает сам: LLM предлагает идеи, агент проверяет каждую
по реальным товарам Amazon (сколько хороших товаров, рейтинги, цены в
диапазоне $20–120) и строит сайты по лучшим. Он держит минимум
`AUTO_NICHES` сайтов (по умолчанию 3); если выключить или удалить сайт,
на его место будет подобрана новая ниша. Кнопка «Подобрать сам» в панели
запускает подбор сразу, а свою нишу по-прежнему можно добавить вручную.

## Товары из Creator Connections

Кампании Creator Connections платят бонус сверх обычной комиссии. В
Creators API нет метода, который отдаёт их список, поэтому их импортируют
вставкой: в Associates Central откройте Creator Connections → вкладка
**Accepted** (бонус платят только по принятым кампаниям) → Ctrl+A, Ctrl+C
→ в панели блок «Импорт из Creator Connections» → вставить →
«Импортировать».

Агент вытащит из текста все ASIN и их Estimated EPC, получит по API
актуальные рейтинг, отзывы, цену и место в продажах, отсеет слабые товары
и выставит до 30 лучших на отдельный сайт (число меняется в настройках
панели: «Товаров на сайт (импорт)», до 500). Товары с высоким EPC стоят
выше, поэтому пуш-кампании в первую очередь запускаются на них. Повторный
импорт с тем же названием сайта добавляет товары в тот же сайт.

**Запасной режим без API.** Если Creators API отказывает (например,
`AssociateNotEligible` в первые 48 часов после создания ключей), агент
строит сайт из самой вставленной страницы: название, бренд, EPC; рейтинг
и число отзывов со страницы используются только для ранжирования. Фото,
цены и рейтинги на сайте не показываются — без API это запрещено
правилами Amazon, — а ссылки ведут на `amazon.com/dp/ASIN?tag=ВАШ_ТЕГ`.
Как только API заработает, агент сам заменит такие страницы полноценными
и перепишет тексты. Пока фото нет, агент рисует через OpenAI иллюстрацию
по типу товара (до `ILLUSTRATIONS_PER_RUN` за цикл, ~$0.04 за штуку) с
пометкой «Illustration — not the actual product photo»; выключается
`SITE_ILLUSTRATIONS=false`.

«Budget availability score» тоже читается со страницы: товары с **High**
(бонусного бюджета у бренда много) стоят выше и рекламируются первыми,
**Medium** — после них, а **Low** (бюджет почти кончился, останется только
обычная комиссия) агент сам не рекламирует — такой товар можно запустить
вручную кнопкой «Запустить рекламу». Оценка обновляется при повторном
импорте той же страницы.

«Up to $2.50» — это верхняя оценка Amazon, а не гарантия, поэтому EPC
учитывается в ранжировании вместе с отзывами и продажами, а не вместо них.

## Разделы и подборки на сайте

Чтобы сайт не был «просто списком товаров», агент раскладывает товары по
разделам («Air Purifiers», «Car Accessories» …) и для каждого пишет
подборку-сравнение `/s/<сайт>/c/<раздел>`: вступление, таблица сравнения
(для кого подходит, главные характеристики из Amazon, кнопка на Amazon),
советы по выбору, разбор каждого товара и итог. Главная сайта показывает
разделы с лучшими товарами, страница товара — ссылку на свой раздел и
похожие товары; подборки попадают в sitemap. Всё пишется только из данных
Amazon API (название, бренд, характеристики) — без выдуманных фактов.
Пересобирается, когда набор товаров заметно изменился (добавлено ≥5 или
убрано ≥ max(3, 10%)), не чаще раза в 12 часов (новые товары до этого видны
в «More Picks»); стоит ~$0.20–0.40 за сборку.

### Как у обзорных изданий (по образцу Wirecutter)

- В подборках метки **Our pick / Runner-up / Budget pick / Upgrade pick**
  (бюджетный и премиум — по текущим ценам Amazon), блоки «Who this is for»,
  «How we picked» (честно: без тестов руками), «Care and maintenance»,
  «Other products we considered», FAQ.
- **Статьи-советы**: 2–3 на раздел — как выбрать, частые ошибки, уход
  (`/s/<сайт>/a/<статья>`, список — `/advice`): общие советы, без моделей,
  цен и «мы протестировали». Пишутся по 12 за цикл и не переписываются при
  пересборке разделов.
- **Сравнения «X vs Y»** двух лучших товаров раздела
  (`/s/<сайт>/vs/<сравнение>`): таблица характеристик из Amazon, кому что
  подходит, итог.
- **Подарочные и сезонные подборки** (`/s/<сайт>/g/<подборка>`, список —
  `/gifts`): «Gift Ideas Under $25/$50/$100» и сезонная (по месяцу).
  Обновляются раз в неделю и при смене сезона; товар дороже бюджета по
  сегодняшней цене Amazon из подборки скрывается.
- **Скидки** `/deals`: товары, на которые Amazon сейчас показывает скидку
  от 10% (процент и цена из API, с временем).
- Главная: популярные подборки (по визитам за неделю), скидки, лучшие
  товары, разделы, подарки, сравнения, советы, «How we choose». В меню —
  Guides, Deals, Gifts, Advice.

## Как устроен цикл

```
каждые N часов, для каждой ниши:
  Creators API: поиск (20 товаров) ─► отбор (рейтинг ≥ 4.0, отзывов ≥ 100, есть цена и фото)
                                   ─► топ-12 на сайт, тексты от LLM для новых товаров
затем по всем кампаниям:
  PropellerAds: расход ─► правило отключения ─► чёрный список зон ─► новые кампании в пределах лимита
```

Путь посетителя: пуш → страница товара на **вашем** сайте
(`/s/<ниша>/p/<ASIN>?c=<кампания>&z=<зона>`) → кнопка «Check price on Amazon»
→ `/go/...` (клик записывается) → Amazon с вашим партнёрским тегом.

Amazon не передаёт конверсии обратно, поэтому агент оптимизирует по
**стоимости клика на Amazon**: расход кампании / клики с сайта на Amazon.

## Картинки для пушей

При `PUSH_CREATIVES=ai` (по умолчанию) агент для каждой кампании:
1. просит LLM описать `PUSH_CREATIVE_VARIANTS` разных фото-сцен по типу
   товара (без брендов, логотипов, текста и фото с Amazon — их в рекламе
   использовать нельзя);
2. рисует их через OpenAI (`OPENAI_IMAGE_MODEL`, по умолчанию `gpt-image-1`,
   качество `OPENAI_IMAGE_QUALITY`) — примерно $0.05 за картинку;
3. режет каждую на картинку пуша 492×328 и иконку 192×192;
4. кладёт все варианты в одну кампанию — сеть сама крутит их и чаще
   показывает лучший.

Если генерация не удалась (нет ключа, не пройдена верификация организации
в OpenAI, лимиты), агент пишет об этом в журнал и берёт простые картинки —
запуск не останавливается. Превью картинок видно в таблице кампаний;
кнопка «Перерисовать» делает новые для тестовой кампании.

## Защита бюджета

Бюджеты, лимиты, ставку, страны, правила отключения и включение рекламы
можно менять в панели: «⚙ Настройки рекламы и бюджета». Значения из
панели хранятся в базе и перекрывают `.env`, применяются без перезапуска.
Новый бюджет кампании применяется и к уже запущенным; если общий лимит
снизили ниже текущего расхода, агент остановит самые новые кампании.

| Правило | Настройка | По умолчанию |
|---|---|---|
| Тестовый режим: ничего не отправляется в PropellerAds | `PUSH_LIVE` | `false` |
| Общий лимит суммы дневных бюджетов всех активных кампаний | `MAX_DAILY_SPEND` | $30 |
| Бюджет одной кампании в день (минимум PropellerAds — $10) | `CAMPAIGN_DAILY_BUDGET` | $10 |
| Кампаний на один сайт | `CAMPAIGNS_PER_SITE` | 3 |
| Тест товара: после $X расхода кампанию отключают, если на Amazon перешло меньше Y% посетителей (проверка каждые 3 минуты, расход считается и по визитам) | `KILL_MIN_SPEND`, `MIN_AMAZON_RATE` | $1, 1% |
| Дополнительно (по желанию): отключать, если переход на Amazon дороже $Z | `MAX_COST_PER_AMAZON_CLICK` | 0 = выключено |
| Зона с расходом ≥ $Z и 0 кликов → чёрный список | `ZONE_MIN_SPEND` | $1 |
| Растягивать дневной бюджет кампании на сутки (день кампании — с 00:00 UTC): обогнавшая равномерный график кампания ставится на паузу «растягиваю бюджет» и включается, когда время её догонит | `PACE_DAILY_BUDGET` | включено |
| Платформа новых кампаний: все устройства, только мобильные (телефоны и планшеты) или только ПК. Значения таргетинга `os_type` агент берёт из справочника PropellerAds | `PUSH_PLATFORM` (`all` / `mobile` / `desktop`) | `all` |
| Кнопка «Стоп всё» в панели | — | — |

Товар, кампанию по которому отключило правило (или вы вручную), агент
больше не запускает повторно.

## Запуск

```bash
cd amazon_agent
cp .env.example .env
python -m amzagent.security "ваш-пароль"                 # -> ADMIN_PASSWORD_HASH
python -c "import secrets; print(secrets.token_hex(32))"  # -> SECRET_KEY
# заполните .env: ключи Amazon, PropellerAds, LLM, DOMAIN

docker compose up -d --build
```

На `https://ВАШ_ДОМЕН/` — публичная главная со всеми сайтами агента.
Панель управления — `https://ВАШ_ДОМЕН/admin`: войдите, добавьте нишу. Агент сразу
соберёт сайт и **тестовые** кампании.

### Перед включением реальной рекламы

1. Откройте в панели payload любой тестовой кампании.
2. Сверьте его с актуальной документацией PropellerAds:
   https://ssp-api.propellerads.com/v5/docs/ — названия полей и пути
   собраны в одном месте: `amzagent/push/propeller.py` (константы вверху и
   `build_campaign_payload`). Из среды разработки документация была
   недоступна, поэтому эту сверку нужно сделать один раз вручную —
   особенно формат креативов (иконка/картинка как URL или загрузка файла)
   и макросы `${ZONEID}` / `${SUBID}` в ссылке.
3. Поставьте `PUSH_LIVE=true` и перезапустите: `docker compose up -d`.
   Тестовые кампании будут закрыты, и агент запустит настоящие.

### Автообновление

Один раз на сервере:

```bash
cd ~/Agent/amazon_agent && git pull && bash deploy/install-autoupdate.sh
```

После этого сервер каждые 5 минут проверяет GitHub и, если вышла новая
версия, сам скачивает её и пересобирает агента (`deploy/autoupdate.sh`).
Версия и время обновления видны в панели рядом с заголовком, журнал —
`/var/log/amzagent-update.log`. Отключить: `crontab -e` и удалить строку
с `autoupdate.sh`.

Локально без Docker:

```bash
pip install -r requirements.txt
SESSION_HTTPS_ONLY=false python -m amzagent.web   # http://localhost:8000
pytest                                            # тесты, полностью офлайн
```

## Посетители без рекламы

Скрипт на каждой странице сайта сообщает о просмотре (`/pv`), если
посетитель пришёл не с нашей рекламы (у рекламных заходов есть `?c=`, и
вся такая сессия пропускается). Считаются только настоящие браузеры: боты
по User-Agent и владелец, вошедший в панель, не учитываются. В панели,
блок «Посетители без рекламы»: заходы, примерно людей (по хэшу IP),
доля с телефонов, просмотры страниц и переходы на Amazon без рекламы — за
24 ч, 7 и 30 дней; источники (Google, Bing, соцсети, прямые заходы…) и
страницы входа за 30 дней.

## Фильтр ботов

Все кнопки «на Amazon» ведут через `/go/…`. Клик **не пропускается на
Amazon с нашим тегом**, если он похож на автоматический:

- User-Agent бота, краулера или скрипта (curl, python, headless…);
- браузер под управлением автоматики (`navigator.webdriver`);
- нет отметки нашего скрипта на странице (ссылку открыли напрямую, без JS);
- клик раньше чем через 2 секунды после открытия страницы;
- больше 5 кликов на Amazon за час с одного адреса (хранится только
  хэш IP).

Вместо перехода показывается страница «Continue to Amazon». Для мягких
причин (нет JS, слишком быстро) в настоящем браузере кнопка ведёт на нашу
ссылку, так что человек проходит одним нажатием, а бот получает только
ссылку без тега. Задержанные клики видны в панели как «🤖 N задержано» у
кампании и зоны (в подсказке — причины) и не считаются переходами на
Amazon. Зона, где задержано не меньше `BOT_ZONE_MIN` (3) кликов и их не
меньше, чем настоящих, отключается автоматически — в обоих режимах и у
вайт-листов (0 = не отключать).

Второе правило — по поведению: зона без переходов на Amazon, где из
`BOUNCE_ZONE_MIN_VISITS` (8) визитов с замером времени `BOUNCE_ZONE_PCT`
(80) % ушли быстрее 5 секунд или страница вообще не прислала сигнал (боты,
случайные клики), тоже отключается — в обоих режимах и у вайт-листов.
Визиты младше 2 минут не учитываются: они могли ещё не прислать время.

## Время на сайте

Страница товара раз в 15 секунд и при уходе сообщает серверу, сколько
секунд она была на экране (скрытая вкладка не считается; без cookie,
запрос подписан, чтобы время нельзя было подделать). В панели под
визитами кампании и каждой зоны: **⏱ среднее время · отказ %** — доля
визитов короче 5 секунд, включая страницы, которые ничего не прислали
(боты, мгновенное закрытие). Считается для визитов после обновления.

## Режим: авто или ручной

Переключатель «Режим: Авто | Ручной» вверху панели.

- **Авто** (по умолчанию): агент сам запускает кампании по лучшим товарам,
  отключает провалившие тест, чистит зоны и подбирает новые ниши.
- **Ручной**: агент продолжает обновлять сайты, собирать статистику и
  следить за деньгами (лимит за 24 ч, аварийная остановка), но решений по
  кампаниям не принимает. Рекламу запускаете вы: «Сайты» → «Товары ▾» →
  «Запустить рекламу» (или в чате: «запусти рекламу на B0...»);
  останавливаете и возвращаете — кнопками кампаний; зоны — в «Зоны ▾».
  Вайт-лист: в «Зоны ▾» отметьте зоны (с переходами на Amazon отмечены
  заранее) → «Создать кампанию только с отмеченными зонами». Агент создаёт
  новую кампанию на тот же товар с таргетингом только на эти зоны (лимит за
  24 ч действует); исходная продолжает работать. Зоны вайт-листа агент не
  отключает и по результатам его не останавливает.
  Галочка «В ручном режиме тоже отключать зоны» (`MANUAL_PRUNE_ZONES`,
  включена по умолчанию): агент и тут отключает у всех работающих
  кампаний зоны без переходов на Amazon по порогам «Зона без переходов».

Кнопка «Запустить рекламу» работает и в авто-режиме — например, чтобы
вручную дать второй шанс товару, который агент отключил.

## Чат с агентом

Кнопка «💬 Чат с агентом» в правом нижнем углу панели. Агенту можно писать
обычным языком:

- спросить: «как дела у Lutron?», «почему отключили #5?», «сколько
  потрачено за сутки?», «какие зоны у #6 дают переходы?»;
- попросить: «останови #8», «верни #6», «отключи зону 123 у #6»,
  «подними лимит до $40», «запусти цикл», «стоп всё».

Агент берёт цифры из той же базы и PropellerAds, что и панель, а действия
выполняет теми же функциями, что и кнопки, поэтому лимиты и проверки
действуют. Каждое действие из чата записывается в журнал с пометкой «чат:».
Если просьба неоднозначна или увеличит расходы, агент сначала переспросит.
Работает на той же нейросети, что и тексты (`LLM_PROVIDER`), — один ответ
стоит примерно $0.01–0.03.

### Советы агента в чате

Раз в час (галочка «Агент пишет советы в чат», `AGENT_ADVICE`) агент
смотрит кампании и зоны и пишет в чат «💡 Советы агента» — то, что он сам
не делает: мёртвые зоны в вайт-листах (и в ручном режиме без чистки зон),
зоны, достойные вайт-листа, выгодную кампанию на паузе «растягиваю
бюджет», убыточную кампанию, которую правила не останавливают, бюджет
бонусов Low/Medium, слишком низкий EPC. Советы строятся по правилам (без
OpenAI), каждый пишется один раз; на кнопке чата — число непрочитанных.
Ответ «сделай» — агент выполнит советы своими инструментами.

## Правила Amazon, которые агент соблюдает

- Страницы, которые проверяет Amazon при ревью сайта: `/about`, `/contact`
  (форма связи — сообщения видны в панели), `/privacy` (с обязательным
  пунктом о cookies Amazon и третьих сторон), `/terms`,
  `/affiliate-disclosure`; ссылки на них в подвале каждой страницы. Плюс
  `/sitemap.xml`, `/robots.txt`, значок сайта. `CONTACT_EMAIL` в `.env`
  добавит email на страницы Contact и Privacy.

- На каждой странице — раскрытие «As an Amazon Associate we earn from
  qualifying purchases».
- Цена показывается только если получена из API менее 24 часов назад, с
  датой и обязательной оговоркой; устаревшая цена скрывается. Поэтому
  держите `AGENT_INTERVAL_HOURS` ≤ 24.
- Картинки товаров подгружаются с серверов Amazon, не копируются.
- В рекламе **нет** прямых партнёрских ссылок и фото товаров Amazon: пуш
  ведёт на ваш сайт, а картинки креативов агент рисует сам
  (`amzagent/push/creatives.py`).
- Тексты не содержат цен, скидок, выдуманных характеристик и срочности
  (жёсткие правила в промптах `amzagent/content/writer.py`).

Риск, о котором стоит знать: пуш-трафик дешёвый, но низкого качества.
Amazon следит за качеством трафика и может закрыть аккаунт Associates при
большом числе кликов без покупок. Начинайте с маленького лимита и
смотрите отчёт по заработку в Associates Central.

## Структура

```
amzagent/
├── amazon/catalog.py      Creators API: поиск и получение товаров
├── amazon/creator_connections.py  разбор вставленной страницы Creator Connections
├── selection/selector.py  фильтр и ранжирование товаров
├── selection/niches.py    автоподбор ниш (идеи LLM + проверка по Amazon)
├── content/               LLM и генерация текстов (сайт + пуши)
├── push/propeller.py      PropellerAds SSP API v5
├── push/creatives.py      простые иконка и картинка для пуша (Pillow)
├── push/ai_creatives.py   картинки для пушей нейросетью (OpenAI)
├── agent/runner.py        автономный цикл и правила бюджета
├── store.py               SQLite: ниши, товары, кампании, события, журнал
├── site/templates/        шаблоны публичных сайтов
└── web/                   FastAPI: сайты, трекинг, панель управления
```
